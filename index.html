Onkio

Library

A rekordbox collection export is the best input. It already carries BPM and key analysis. In rekordbox: File → Export Collection in xml format. An Apple Music Library.xml also works, but carries no BPM or key. Several files can be loaded at once. They are laid out in one shared space, and each keeps its own colour and its own coverage, so a crate that already has BPM and key is never confused with one that needs looking up.

Music folder

Point Onkio at the folder holding the audio and tracks play from the files themselves instead of from a 30-second preview. That covers personal edits, remixes and unreleased bounces, which no catalogue carries a preview for. Files are matched automatically against the paths already recorded in the collection export, so there is nothing to attach track by track. A folder moved to another machine still matches, because the end of each path is what gets compared. Nothing is uploaded, copied or changed. The folder is read inside the browser only, and it is remembered between visits, though each new visit needs one click to grant reading again. Needs a Chromium browser: Chrome, Edge, Brave, Arc or Opera. Firefox and Safari have no way to grant a folder, and previews stay the only source of audio there.

Map

Sound

Listens to each track and measures how it actually sounds (brightness, texture, how percussive it is) so the map can be built from the audio instead of from how tracks are filed. With a music folder connected it listens to the files themselves, which reaches the personal edits and bounces that have no preview. Without one it falls back to 30-second previews, and those exist for catalogue tracks only, roughly two thirds of a typical DJ crate. Tracks that could not be heard are drawn as hollow rings and stay positioned by metadata, so the map does not pretend to know how they sound. A file is sampled for the same 30 seconds a preview would give, taken from a third of the way in. Measuring whole tracks alongside short previews would sort the map by which tracks had files rather than by how they sound.
Sound influence (advanced)
Sets how much the measured audio counts when the map is laid out, against BPM, key, genre and playlist company. At zero the layout ignores sound entirely. Only tracks that have been analyzed can move, so run the analysis first. Changing this rebuilds the whole map.

GetSongBPM (optional key)

BPM & key data from GetSongBPM

GetSongBPM is the only source of musical key that does not require analyzing audio. Add a free API key to switch it on. The browser reads the API directly, so no proxy is needed. The proxy field is a fallback in case that stops working. Leave both blank to skip. Measured on 1,000 tracks of an Apple Music library: 31% came back with both BPM and key, at about a second and a half each. Matches found on title alone are the unreliable tail and are rejected.
Best-effort only, and aimed at the tracks that need it: a collection that already carries BPM and key is skipped entirely, so lookups are never spent re-learning what a rekordbox export already knows. Deezer: BPM where available, plus a 30s preview for nearly everything. Browser analysis: estimates key and BPM from previews. Pan the map and run again to expand. Expect roughly a third of a catalogue library to resolve, at about two seconds each. A rekordbox export remains the only reliable way to fill these in.
